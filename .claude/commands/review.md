# /review

对代码进行审查。可选参数：`/review [路径或 git 范围]`，例如 `/review src/auth` 或 `/review HEAD~1`。无参数时审查当前未提交的改动。

## 步骤

1. **确定审查范围**
   - 无参数：`git status` + `git diff`（含未暂存与已暂存）
   - 参数是路径：审查该路径下的文件
   - 参数是 git 范围（如 `HEAD~1`、`main..HEAD`）：`git diff <范围>`
2. **逐文件审查**，重点关注：
   - 正确性 bug、边界情况、错误处理
   - 安全风险：注入、越权、密钥/敏感信息泄露、不安全的反序列化
   - 性能：不必要的嵌套循环、N+1 查询、大对象拷贝
   - 可读性、命名、重复代码、是否引入回归
3. **分级输出**（按严重程度从高到低）：
   - 🔴 必须修复 —— 会导致 bug / 安全问题 / 数据丢失
   - 🟡 建议改进 —— 影响可维护性或存在隐患
   - 🟢 写得不错 —— 值得保留的好实践

   每条给出 `文件:行号` + 问题 + 简要修复建议。
4. **不要自动修改代码**。结尾给出一句话总体评价。

若范围内没有任何改动，明确告知用户。
